# Fewer plan runs: complete first reviews, a form-first prompt, the frame on rejection, fewer re-asks

Six changes to the plan loop, each removing a specific turn: (1) every first plan review gets the completeness checklist, not only Autopilot's; (2)+(4) the plan instructions settle the design before the format and carry one complete exemplar; (3) the repair frame is handed over on the first format rejection in every mode; (5) the reviewer is asked for a missing verdict only where it can change something; (6) every hold result offers `edits`. Nothing changes in stored settings, the wire protocol or the tool schema.

## Decisions

- Change 1 reverses a behaviour a test pins (`plan_review.rs:2672` asserts Plan mode's brief lacks the checklist). The test is updated deliberately because the pinned behaviour is what this request changes, and the new arm is stricter (Autopilot keeps the criteria bullet, Plan mode gains the rest) — not a weakened test.
- Change 2 keeps the four sentinel strings byte-identical rather than renaming them: `plan_mode_instructions` replaces text and `plan_form` slices by those strings, and a rename would silently no-op instead of failing (`plan/tests.rs:20` is what catches it).
- Change 3 is one exemplar on purpose: the over-prompting evidence says more examples degrade some models, so the existing inline step example is replaced, not kept alongside. The exemplar stays criteria-free because `AUTOPILOT_CRITERIA` already says where criteria go and the frame supplies them.
- Change 5 accepts one loss: a verdict the reviewer omitted on a step the revision did not touch is skipped, and the finding settles — the state today's `NOT_CHECKED_REASON` fallback already produces. A reviewer that still considers it a problem reopens it by repeating it with evidence, which needs no verdict. An empty `changed` is no filter at all, so a change review's follow-up (`change_review.rs:1288`, which sets no changed steps) keeps asking for every missing verdict.
- Change 6 keeps the two answer-shape numbers apart (`first`, `second`) rather than deriving both from one, so the plain message reads exactly as it does today and `ledger_result` keeps writing its F-number twice; no existing assertion changes.
- Change 6 uses `submit_plan`'s existing `edits` argument, so the tool schema in `tools.rs` is untouched.
- No new fields reach stored settings or `rovik-protocol` types, so no serde defaults are needed.

## Validation

- `cd src-tauri && cargo nextest run -p rovik-core`, then `cargo test -p rovik-core` for the tests that take a process-wide lock.
- `cargo clippy -p rovik-core --tests` adds no warnings; `rustfmt --edition 2021` on the changed files only.
- New and updated tests: the brief test (step 1); the prompt-order and `plan_form` tests (steps 2–3); the skeleton test and the bad-plan e2e (step 4); `verdicts_worth_asking` and the follow-up verdict e2e (step 5); the hold-result `edits` assertions (step 6).
- By hand: a Plan-mode run whose first submit is vague — one rejection carrying the frame; then a good plan — its first review reports callers/order/scope, and the second round is a follow-up with few new findings; a held plan revised with `edits` saves in one turn.
- Before a commit, the full gate still applies: `npm test`, `npm run typecheck`, `npm run format:check` (no TS changed, but they must pass).

## Risks

- The prompt text (steps 2–3) is the least measurable change. Read `planSubmit` (`execute.rs:2240`) and `planReview` (`plan_review.rs:2130`) before and after: if round-1 findings do not drop and `formatRejections` does not fall, revert both — they are text-only.
- Step 1 makes every first review's brief longer; a reviewer near its 25-call budget may read less. It applies to first reviews only.
- Step 4 grows the rejection result by the frame, bounded by the plan's own 40,000-character limit.
- Step 5 can let an unresolved finding pass where the reviewer omitted a verdict on an unchanged step — the accepted cost above.
- Steps 2 and 3 edit the same region of `plan/prompt.rs`; apply in order and re-read before the second edit.
- `plan_form()` now carries the exemplar, so a Thorough task's planner briefs grow by roughly 300 words each; the documented escape hatch is moving the exemplar past the pre-submit sentinel.
- Step 5 changes what an existing e2e asserts (`a_follow_up_without_verdicts_is_asked_for_them`): the new expectation is deliberate — that finding is on a step the revision leaves alone — and the added rewrite case keeps the ask covered.
